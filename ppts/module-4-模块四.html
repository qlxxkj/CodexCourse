第 12 课

如何写出更好的指令

03 / 15
模块四

指令质量决定结果质量

好的指令 = 清晰的目标 + 具体的要求 + 明确的验收标准
❌ 差的指令
"帮我做一个网站"
太模糊，不知道什么类型、什么风格、包含哪些内容。
✅ 好一些
"帮我做一个个人简介网页"
好一些，但还是不够具体。
✅✅ 更好的指令
帮我做一个个人简介网页，要求： 1. 包含头像、姓名、简介、技能列表、联系方式 2. 简洁现代的设计风格 3. 主色调为蓝色 4. 代码保存为 index.html

模块四

关键技巧：先计划、再执行

技巧一：提供背景信息
整理照片："去年去日本旅行拍的照片，按城市分类"
写邮件："给客户邮件，语气正式，主题是项目延期"
数据分析："销售数据，包含日期、产品、数量、金额四列"
技巧二：让 Codex 先给计划
在开始之前，先告诉我你的执行计划， 等我确认后你再开始
✅ 确认 Codex 理解了你的需求
✅ 调整计划中的任何偏差
✅ 避免做无用功

模块四

指令模板

文件操作类
请帮我 [动作] [对象]， [具体要求]，[验收标准]
例：帮我把文件夹里的图片按日期分类
内容生成类
请帮我 [动作] 一个 [类型]， 关于 [主题]，要求 [格式/风格]
例：写一份健康饮食周报，分三个部分
数据分析类
请帮我分析 [数据源]， 找出 [关注点]，输出 [格式]
例：分析销售数据，找出增长最快的产品

第 13 课

安全与权限管理

07 / 15
模块四

为什么要有权限管理？

⚠️ 核心原因
Codex 能操作你的文件——读取、修改、删除
这意味着它既有强大的能力，也有潜在的风险。权限管理的核心目的：确保 Codex 只在授权范围内使用，保护你的数据安全。
✅ 应该做的
📌 备份重要文件
📌 使用默认权限
📌 审阅每次结果
📌 限制工作区范围
❌ 不应该做的
🚫 输入密码、银行卡信息
🚫 给完全访问权限
🚫 不检查 Codex 的输出
🚫 让 Codex 操作系统关键目录
三种权限模式
默认权限 — 每次操作前征求同意
自动审查 — 事后审计，效率更高
完全访问 — 高风险，不建议

模块四

实操：设置权限

Step 1
打开设置界面
找到"权限管理"或"安全设置"
Step 2
选择默认权限模式
刚开始使用时保持默认权限，最安全
Step 3
测试验证
让 Codex 执行一个文件操作，观察它如何征求你的同意
权限示例
Codex：我打算创建子文件夹 "images"，并将所有图片移入。 是否允许？ 你：[允许 / 拒绝]
安全原则
最小权限原则
只给 Codex 完成工作所需的最小权限，用完即收回。

模块四

用"验收标准"告诉 Codex 什么叫做好了

示例：整理文档
帮我整理这份文档，要求： 1. 去除所有空行 2. 统一标题格式（一级标题用 # 二级标题用 ##） 3. 检查并修正错别字 4. 最后告诉我你做了哪些修改
关键技巧
让 Codex 告诉你它做了什么
注意最后一条——让 Codex 告诉你它做了什么，这样你可以快速验证结果是否符合预期。
好处
✅ 快速验证结果是否正确
✅ 发现遗漏的细节
✅ 方便后续追问和调整

Codex 的"技能"（Skills）

12 / 15
模块四

什么是"技能"？

技能是 Codex 内置的预置工作模板——每个技能都是为特定类型的任务预先优化过的。
没有技能
"帮我做 PPT"
Codex 从零开始猜怎么做，效率低，质量不稳定。
有技能
"用 PPT 技能帮我做演示文稿"
Codex 直接套用最佳实践，更高效、质量更稳定。
